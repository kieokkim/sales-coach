# 기능 추가 판단 필터

이 프로젝트(TradeCoach / SalesCoach)의 제0원칙:
에이전트의 가치는 **판단 품질**에 있다. 인프라·편의 기능이 판단 코어를 앞지르면
"기술 스택은 화려한데 판단은 검증 안 된" 상태가 된다.

## 새 기능 요청을 받으면 반드시 먼저 물을 것

**"이것이 판단 품질과 직결되는가?"**

세 가지로 분류한다:

1. **판단 코어 (즉시 진행)**
   - rule-based 탐지 로직 개선, ground truth 검증, eval 정밀화,
     스키마가 판단 표현을 왜곡하는 문제 수정
   - 예: anchor_set 라벨링, top_issue 스키마 재검토, A+ 스코어링 look-ahead 수정

2. **판단 보조 (조건부)**
   - 판단 결과를 더 잘 전달하거나(설명), 판단 근거 데이터를 넓히는 것
   - 진행하되, 판단 코어가 검증된 다음인지 확인. 코어가 미검증이면 보류 우선.

3. **판단 무관 (보류 목록으로)**
   - 인프라(FastAPI/Langfuse 추가 확장), 편의 기능(날씨 연동, 재고 시그널),
     UI 미화, 새 데이터 소스 연결
   - "지금 이걸 하면 판단 품질이 올라가는가?"에 No면 보류.
   - 보류 결정도 이유와 함께 기록(DECISION_LOG 후보).

## 응답 형식

기능 요청 시 코드를 쓰기 전에:
1. 위 3분류 중 어디인지 한 줄로 판정
2. 판단 무관/보조인데 코어가 미검증이면 → "이것보다 먼저 할 것"을 제시
3. 사용자가 그래도 진행을 원하면 진행하되, 트레이드오프를 명시

## 현재 미검증 판단 코어 (2026-07 기준)
- SalesCoach: anchor_set 9항목 확보, category는 rule과 6/6 일치 확인됨.
  severity 축은 2/6 갈림 확인되었으나 eval이 severity 미채점 - 이 부분만
  아직 검증 공백.
- TradeCoach: A+ 스코어링 58%의 ground truth 미검증

이 두 개가 남아있는 동안, 새 인프라·기능 추가는 기본적으로 보류 쪽으로 판정한다.
